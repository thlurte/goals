  1. **GPU Top-$k$ Selection vs Full Global Sort**:
     * Sorting all $N = 1{,}000{,}000$ distance values using `cub::DeviceRadixSort` requires $\approx 8\text{ MB}$ extra global memory writes and $\approx 1.2\text{ ms}$ compute time.
     * Warp-Cooperative Top-$k$ Selection:
       * Each thread maintains a small sorted register array (e.g. 4 entries).
       * Warps merge candidates in registers using Bitonic Compare-and-Swap networks executed via `__shfl_xor_sync`.
       * Only the final top-$k$ items ($k \le 100$) are written back to global memory, cutting memory bandwidth by $>98\%$.

     ```cuda
     #pragma once
     #include <cuda_runtime.h>

     namespace secan {
     struct NeighborPair {
         float dist;
         uint32_t id;
     };

     // In-register warp bitonic sorting network for 32 pairs
     __device__ inline void warp_bitonic_sort_32(NeighborPair& item) {
         #pragma unroll
         for (int stage = 2; stage <= 32; stage <<= 1) {
             for (int step = stage >> 1; step > 0; step >>= 1) {
                 float other_dist = __shfl_xor_sync(0xffffffff, item.dist, step);
                 uint32_t other_id = __shfl_xor_sync(0xffffffff, item.id, step);
                 bool direction = ((threadIdx.x & stage) != 0);

                 if ((item.dist > other_dist) == direction) {
                     item.dist = other_dist;
                     item.id = other_id;
                 }
             }
         }
     }
     }
     ```
